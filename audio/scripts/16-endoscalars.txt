Chapter sixteen. Endoscalars.

The curve cycles chapter, chapter thirteen, left a promise open. It split each fold between two circuits and let one transcript supply the challenges for both. In its toy run the challenges crossed between the circuits as small integers, and the secondary circuit used them in plain double-and-add. That chapter also noted that Ragu's code does something else, because in the code a short value maps to a scalar that is not the plain integer.

This chapter supplies that map. We start from a symmetry of the curves that makes one particular large scalar free to apply, and we build a way of reading a short bit string that uses this symmetry at every step. The same string then acts as one scalar in each field of the cycle, which is what lets a challenge cross. After that we count the gates, show why distinct strings stay distinct on Pasta and fail to on the toy curves, and rerun the fold from chapter thirteen with the real map.

Much of this chapter is reconstructed from the code at the commit this site pins, and the authors have not confirmed it. The radix-three encoding, its cost and its injectivity argument come from the Ragu Book and the code, and our script reruns them. Our descriptions of how the code uses the encoding are also reconstructed from the code. The toy fold later in the chapter is our own small assembly of that usage, and its width of five bits has no counterpart in Ragu.

A few terms will recur. An endoscalar is the bit string itself, and its length is one hundred forty-three bits in Ragu. Endoscaling means multiplying a point by the string. Lifting means computing the scalar that the string stands for in a given field. We treat the first bit of a string as the least significant, as the code does.

We also keep the names from chapter thirteen. The primary circuit has wires in the field of size forty-three on the toy cycle, and the code calls it the native side. The secondary circuit has wires in the field of size thirty-one, and the code calls it the nested side.

What the plain integer costs.

A short integer does fit in both fields, so the plain approach of chapter thirteen can work in principle. Its trouble is the price. In Ragu's code a fuse folds ninety-three points of Pallas and one hundred five points of Vesta with one challenge, counts that we derive near the end of the chapter. A Horner fold of ninety-three points makes ninety-two multiplications by the challenge, one for each point after the first, and the other fold makes one hundred four.

A Ragu circuit holds only two to the eleven gates. The double-and-add from the recursive proofs chapter spends about ten gates on every bit. So one multiplication by a challenge of one hundred forty-three bits would fill most of a circuit.

The way to reduce that price is to get several bits of scalar out of each point addition, and this needs a supply of multiples of the base point that cost nothing to compute. Curves whose equation sets y squared equal to x cubed plus a constant have such a supply. Using it gives up the plain integer, though, so we then have to check that the circuits still agree on what the string means.

The curve's endomorphism.

That curve equation sees x only through its cube. So take a cube root of one in the coordinate field, called zeta, and replace x with zeta times x. The equation does not change, which means this map sends points of the curve to points of the curve. We'll call the map phi. A cube root other than one exists when the field size is one modulo three, which holds for both toy fields and both Pasta fields.

In the field of size thirty-one, the cube roots of one are one, five and twenty-five, and we take zeta equal to five. The generator with coordinates one and two maps to the point with coordinates five and two, and this image lies on the toy curve.

To be useful for scalar multiplication, the map has to respect addition. Apply phi to both inputs of an addition. The difference of the x-coordinates picks up a factor of zeta, so the slope gets divided by zeta. The new x-coordinate is the slope squared minus the input x-coordinates, and since zeta cubed is one, it comes out as zeta times the old one. In the new y-coordinate the factors of zeta cancel, so it stays the same.

So mapping two points and then adding them gives the same result as adding them and mapping the sum, and the same reasoning covers doubling. A map from a group to itself that respects the operation is called an endomorphism. On the toy curve we confirmed this on all one thousand seven hundred sixty-four ordered pairs of affine points.

Now we use the fact that our curves have prime order. Every point is a multiple of one generator, and phi of that generator is some multiple of it. Because phi respects addition, the same multiple then applies to every other point. So phi multiplies every point by one scalar, which we call its eigenvalue, lambda. This lambda has nothing to do with the fold weight of the revdot chapter.

Applying phi three times multiplies x by zeta cubed, which is one, so lambda cubed is one in the scalar field. Since phi is not the identity map, lambda is not one. Dividing lambda cubed minus one by lambda minus one leaves the relation that lambda squared plus lambda plus one equals zero.

On the toy curve with zeta equal to five, phi multiplies every one of the forty-two affine points by six, so lambda is six. And indeed six squared plus six plus one is forty-three.

This gives us the cheap multiple we asked for. Computing six times the generator by double-and-add would take twenty-one gates for a three-bit scalar. Applying phi takes no gates, because multiplying a wire by the constant five is part of a linear combination. On Pasta, lambda is a scalar of about two hundred fifty-one bits, and multiplying by it with double-and-add would cost about two thousand five hundred one gates.

Negation is free as well, because it only flips the sign of y. So from one point we get six multiples, which are plus and minus one, plus and minus lambda, and plus and minus lambda squared. They cost no gates beyond selecting among them.

One constant for each field.

A combination such as some copies of a point plus some copies of its image acts on that point as some scalar in the field of size forty-three. The secondary circuit computes those point additions over the field of size thirty-one, so it never sees that scalar. The fold of chapter thirteen also needs the same scalar as a number, for the value side, and the primary circuit computes that number.

The primary circuit cannot see the point additions. It can only substitute a constant of its own field for lambda, and the result is right only if its constant is the eigenvalue that phi actually has on the curve. Here is what happens when it is not.

Take three copies of the generator plus two copies of its image, with zeta equal to five. The secondary circuit gets fifteen times the generator, because phi acts as multiplication by six. The primary circuit has to produce the matching number, three plus two lambda, from its own constant. With the constant six it gets fifteen, which agrees.

With the other cube root, thirty-six, the primary circuit gets seventy-five, which is thirty-two modulo forty-three. Thirty-two times the generator is a different point, so the number and the point would describe different scalars.

Each field has two cube roots other than one, and the choice of zeta on the coordinates decides which root of the scalar field is the eigenvalue. We'll call the toy curve with coordinates in the field of size thirty-one the first curve, and its partner the second curve. On the first curve, zeta equal to five gives lambda equal to six, and twenty-five gives thirty-six. On the second curve, zeta equal to six gives lambda equal to five, and thirty-six gives twenty-five.

A field's constant has two jobs. It is the zeta that a circuit over that field applies to the coordinates of the curve whose points it adds. It is also the lambda that the same circuit substitutes when it computes the scalar of a combination on the partner curve. On a cycle both jobs fall on the same field, because the coordinate field of one curve is the scalar field of the other. Ragu therefore keeps one constant per field, called zeta in its code, and uses it for both roles.

That is correct only if the choices line up on both curves. The small field's constant, used as zeta on the first curve, must give the large field's constant as eigenvalue. The large field's constant, used as zeta on the second curve, must give back the small field's constant. Being a cube root other than one does not by itself decide this.

Take five for the small field and six for the large field. Zeta equal to five on the first curve gives six, and zeta equal to six on the second curve gives five, so both conditions hold. The pair five and thirty-six fails, because zeta equal to five still gives six, and that is the mismatch we just saw. The squares, twenty-five and thirty-six, form the other consistent pair.

Once the small field's constant is fixed, the first condition forces the other constant. The second condition is then the real check, since it asks whether that forced constant gives back the first. So a test that keeps one constant and replaces the other with its square breaks a condition.

On Pasta, we tested the pair of constants that the pasta curves crate uses. Multiplying a point of Pallas by one constant gave the same point with its x-coordinate multiplied by the other constant, and the same held on Vesta with the roles swapped. Replacing one constant with its square, while the other stays the same, makes the first test fail.

Ragu reads its constants from a dependency, zakura-udon, which computes them with a macro that we did not evaluate. So we have not confirmed whether Ragu uses this pair or the other consistent pair, made of their squares. The squares pass our test as well, so either choice is consistent. Ragu's own consistency test checks the pairing on both curves for whichever pair it has.

Elements with two images.

We now need a way to talk about a combination of a point and its image under phi without saying which curve the point lies on. Treat lambda as a formal symbol whose square is minus one minus lambda, and work with pairs of integers, written a plus b lambda. These form a ring called the Eisenstein integers, and products follow from the rule for lambda squared.

An element of this ring acts on a point of either curve, and replacing the symbol with the curve's eigenvalue gives the same result as a scalar. Take three plus two lambda. With lambda equal to six, it maps to fifteen in the field of size forty-three. With lambda equal to five, it maps to thirteen in the field of size thirty-one. On each curve, three copies of a point plus two copies of its image give the same point as that scalar multiple.

The rest of the chapter builds on this fact. One element of the ring has an image in each scalar field, and the same rule computes both images from the same pair of integers.

We also need to know when an element has image zero, since that decides when two different elements become the same scalar. The tool is the norm of a plus b lambda, which is a squared, minus a times b, plus b squared. It equals the squared absolute value of the element when we read lambda as a complex cube root of one. So it is never negative, it is zero only for the zero element, and the triangle inequality applies to its square root.

Suppose an element maps to zero modulo a prime. Then a equals minus b lambda modulo that prime. Substituting this into the norm gives b squared, times lambda squared plus lambda plus one, which is zero. So the image can be zero only if the prime divides the norm, and a nonzero element whose norm is below the prime cannot map to zero.

The element five minus lambda has norm thirty-one. With lambda equal to five it maps to zero in the field of size thirty-one, while in the other field it maps to forty-two. The element one plus seven lambda has norm forty-three, and it maps to zero in the field of size forty-three. A search over all coefficients from minus forty to forty found no exception to the rule.

Reading a string as an element.

We want a rule that reads bits into an element, using only cheap multiples, with a large number of bits per point addition. We also want distinct strings to give distinct elements. If two strings gave one scalar, a cheater hoping that the challenge lands on a particular bad value would have two strings that reach it, and so twice the chance.

Consider a running point that we repeatedly multiply by a radix, adding one digit multiple of the base point at each stage. We call this sequence of steps a walk. The cleanest way to guarantee distinct elements is to make the walk decodable. We would recognize the last digit from the element's residue modulo the radix, subtract it, divide by the radix, and repeat on what remains.

Residues of ring elements work coordinate by coordinate, so modulo three there are nine classes, one for each pair of residues of a and b. An element whose a and b are both divisible by three can be divided by three within the ring. So once we subtract a digit from the right class, the division is exact, and decoding works.

That needs digits in distinct classes. We also leave the class zero, zero without a digit, because its natural digit would be zero. Adding zero times a point means adding the point at infinity, which has no coordinates, and the incomplete additions we meet later cannot handle it. Eight nonzero classes also match three bits exactly.

So a tripling walk uses eight nonzero digits and reads three bits for each tripling. The six free multiples fill six classes, and each has norm one. The digit one minus lambda and its negative fill the other two, and each has norm three.

The three bits of a digit are a sign bit and two selector bits. With both selectors off the digit is one. The first selector alone gives lambda, the second alone gives lambda squared, and both together give one minus lambda. The sign bit negates whichever digit the selectors pick.

The last two digits are not free multiples, but they still cost little, as the gate count will show. Halo's original walk uses doubling, with the digits plus and minus one and plus and minus lambda, which gives two bits for each doubling. Modulo two there are only four classes, and those digits already share them in pairs, so Halo tells the members of a pair apart in some other way.

A doubling walk cannot also use plus and minus lambda squared, because two strings then reach exactly the same element. The digit one followed by lambda, and the digit minus lambda squared followed by minus lambda, both give two plus lambda. That is because minus lambda squared equals one plus lambda.

Ragu's layout then reads as follows. The first two bits are a sign and a bit that says whether to apply phi, and together they choose a starting unit. Each later group of three bits is one digit. The walk sets the first running point to twice the starting unit applied to the base point. At each digit, it triples the running point and adds the digit's multiple of the base point.

Expanding this recurrence, the element is twice the starting unit times three to the number of digits. To that we add each digit, times three to the number of digits that come after it. Ragu uses forty-seven digits, and two plus three times forty-seven accounts for the width of one hundred forty-three. A later section shows why it matters that the first running point is more than a single unit.

Because each digit has its own residue, the element determines the string. Take an eleven-bit string with three digits, whose starting unit is lambda. Its digits are one minus lambda, then minus one, then minus lambda, and the walk gives the element six plus forty-four lambda.

Now start from that element alone. Its residues modulo three say it must end in the digit minus lambda. Subtracting that gives six plus forty-five lambda, which is three times two plus fifteen lambda, so the division by three is exact.

The residues of two plus fifteen lambda say the digit before was minus one, and the next residues say one minus lambda. What remains is two lambda, which is twice the starting unit lambda, so the string comes back in full. We enumerated every string with up to four digits, which at four digits means sixteen thousand three hundred eighty-four strings, and no two gave the same element.

One string, two scalars.

Our toy endoscalar has one digit and therefore five bits. The lift function computes the element's image in a chosen field. It runs the Horner form of the expansion, using that field's constant in place of lambda.

Take the string of five ones. Its first two bits make the starting unit minus lambda, and its last three make the digit the negative of one minus lambda. The element comes out as minus one minus five lambda. With lambda equal to six this is twelve in the field of size forty-three, and with lambda equal to five it is five in the field of size thirty-one.

As an integer, the string of five ones is thirty-one, and neither scalar has any simple relation to that number. Other strings show the same independence. The strings with integer values eleven and twenty both lift to thirteen in the larger field, but to six and twelve in the smaller one.

A circuit that needs the scalar as a field value computes the lift in gates, as a Horner loop over the digits. Our traced version spends one gate on the first two bits and two gates per digit. That is three gates for our five-bit string, and on Pasta it is ninety-five gates, just under a fifth of the four hundred eighty gates of one walk.

Endoscaling a point by this string means running the walk with phi and the digit multiples. It needs no knowledge of lambda or of the scalar field, because the circuit only computes with coordinates. The result is still the multiple that the lift predicts, on each curve. For the string of five ones, the walk ends at twelve times the base point on the first curve, and five times the base point on the second.

This matches the book's consistency property, and we can now say why a challenge can cross the cycle. The scalar beta in the field of size forty-three scales polynomials over that field, whose commitments lie on the first curve. The primary circuit computes beta directly by lifting, and it uses the result to fold values.

The secondary circuit cannot hold beta, but it does not need to. It walks points of the first curve by the bits, and the walk acts as beta. The other pair works the same way in the opposite direction.

The bits are all that the two circuits share, and a bit is zero or one in any field. Neither circuit ever handles a number from the other's field. The same equality holds at full size. With the endoscalar from Ragu's own consistency test, the walks on Pallas and on Vesta matched direct multiplication by the lifted scalars, in four hundred eighty gates each.

The walk in gates.

Now we count, using the gates from the recursive proofs chapter. A gate is one multiplication, and a division counts as one multiplication checked backwards. A digit step has two parts, which are picking the digit's point and computing three times the running point plus the digit.

Done naively, the tripling and adding is three additions at three gates each, or nine gates. Two of those gates compute y-coordinates of intermediate points that are never kept. Writing out the second addition's slope and substituting the first addition's formula makes the intermediate y-coordinate disappear. The slope then depends only on the first slope and the running point.

The third addition follows in the same way, and only its output needs a y-coordinate. The code ends up with seven gates.

Choosing among eight points would normally cost gates for each coordinate of each option, because the base point's coordinates are arbitrary wires. The code avoids this by first moving the point to a related curve where its two coordinates are equal. The move multiplies x by the square of a constant and y by its cube, which changes only the curve's constant term.

With the right constant, both new coordinates equal one value, which we'll call r. The addition formulas never read the curve's constant term, so the walk can run on the new curve and move back at the end. For the toy generator, r is eight.

On this curve the free multiples share the y-coordinate r and have x-coordinates r, zeta times r, and zeta squared times r. The fourth digit, one minus lambda, comes from adding the base point to minus its image. That addition has a constant slope, so its coordinates are also a constant times r plus a constant.

So every coordinate of every digit is r times a constant, plus a constant, and only the constants depend on the bits. If the circuit can turn the bits into the right constants with additions alone, a selection needs only one product with r per coordinate. Single bits switch the multiplier of r between one, zeta and zeta squared.

The last row needs a correction that must appear only when both selectors are on. So the circuit multiplies it by the product of the two selector bits. For y, the correction also carries the sign, which needs the product of all three bits. With those two products as wires, a digit costs four gates.

The code's unhoisted gadget, which we call the plain selector, refactors this to save one gate, and our toy run uses it. It computes three products. The second is nonzero only when both selectors are on, so it plays the role of the selector product. The third applies the sign and brings in r together, which saves the gate spent on the three-bit product.

For the string of five ones, all three digit bits are one and r is eight. The three gates produce a point with x-coordinate twenty-two and y-coordinate one. That is the negation of the one minus lambda point, as the sign bit requires. We compared both selectors with direct point arithmetic at every affine point of both curves, and all five hundred seventy-six comparisons agreed.

The walk starts with a doubling, which is cheap on the normalized curve. The tangent slope is three halves of r, which is linear in r, so it costs no gate. Two gates compute the doubled point, and two more apply the sign and phi. After that each digit costs three gates to select and seven to triple and add.

With forty-seven digits, the total is three to normalize, four for the doubling, ten for each digit, and three to move back. That comes to four hundred eighty gates. On our toy string, the tracer counted twenty gates, and moving back to the original curve gave twelve times the generator, as the lift predicts.

A fuse walks many points by one string, so each of those walks repeats the same two bit products for every digit. Ragu hoists them into a stage that the walk circuits share, and one circuit checks them once. With the products arriving as wires, a digit's selection costs two gates where the plain selector spends three.

Here are the costs together. Double-and-add takes one thousand four hundred twenty-one gates for one hundred forty-three bits, close to ten gates per bit. The book's figure for a radix-two walk with the endomorphism is four hundred fifty-five gates for one hundred twenty-eight bits. Radix three takes four hundred eighty gates with the plain selector, and four hundred thirty-three with the hoisted one, which is three point zero three gates per bit.

Our tracer counted the two radix-three figures on a Vesta point, and the results matched direct multiplication by the lifted scalar. A circuit of two thousand forty-eight gates therefore holds one double-and-add multiplication or four hoisted walks. That fits the limit of four endoscalings per circuit that chapter thirteen mentioned.

Why distinct strings stay distinct.

We showed that strings name distinct elements of the ring, but the circuits work in the fields, and a nonzero ring element can have image zero there. The divisibility rule tells us when this can happen, so we bound the norm of a difference between two strings' elements.

Subtract the two elements, term by term. Units have absolute value one, and digits have absolute value at most the square root of three. The powers of three form a geometric sum. Adding up the terms bounds the difference, and squaring that bounds the norm.

The result is three times the square of one less than five times three to the number of digits. The book states this bound without these steps, so the derivation is ours. If the bound is below the field size, the difference cannot have image zero.

With forty-seven digits the bound is about two to the one hundred fifty-five point two, and the Pasta group orders are about two to the two hundred fifty-four. A nonzero difference therefore cannot have a norm divisible by either order, and the strings of one hundred forty-three bits stay distinct in both fields.

The toy curves are far too small for this, and that makes them a useful illustration of what the bound prevents. With one digit the bound is five hundred eighty-eight, and the largest norm that actually occurs is two hundred twenty-eight. Both exceed thirty-one and forty-three, so the argument does not apply.

The thirty-two toy strings reach only twenty-one different scalars in each field. For one clash, two strings give elements whose difference has norm thirty-one, and both map to seven in the field of size thirty-one.

The norm has a second use. The walk uses incomplete additions, which divide by a difference of x-coordinates and so fail if the two inputs are equal or opposite. Those failures require certain combinations of the running point and the digit to be zero, such as their sum, or three times the running point plus the digit.

All of these combinations are nonzero if the running point's absolute value exceeds the square root of three, which bounds every digit. The first running point is twice a unit, so its absolute value is two. Each step triples it and adds a digit, so it only grows, and every digit has norm one or three, so no digit is zero.

So none of these combinations is zero in the ring. Their norms are again below the Pasta group orders, so none has image zero, and the circuit does not need to check these denominators at all. The walk relies on this, because its addition gadget skips that check. On the toy curves the argument does not apply, and we can watch it fail.

We ran all thirty-two strings on every affine point of both curves, which makes two thousand three hundred four walks. Every walk that finished gave the point the lift predicts. On the first curve four strings failed with equal x-coordinates in an addition, and on the second curve six failed.

In one failure on the second curve, the next addition would have reached the element five minus lambda. That is the element of norm thirty-one we met earlier, which is the identity on that curve.

The same reasoning needs a base point with nonzero coordinates, since normalization divides by y. A curve of prime order larger than three has no point with y equal to zero, which would have order two, and none with x equal to zero, which would have order three.

Extracting bits from a challenge.

A transcript produces a field element, and the circuit needs its bits. A field element does not always have a unique bit decomposition inside a circuit, because a circuit checks the weighted sum of the bits modulo the field size. If the bits have enough room to exceed the field size, a prover can choose between spellings.

In the field of size forty-three, a six-bit string can name values up to sixty-three, so twenty-one field elements have two spellings. The element five, for instance, can also be spelled as forty-eight. These spellings have different low bits, so they would name two different endoscalars. If we require the top bit to be zero, each element below thirty-two has one spelling, and the eleven elements from thirty-two to forty-two are rejected.

Ragu therefore requires the value to fit below the largest power of two under the field size, and then it takes the low one hundred forty-three bits of the unique spelling. On Pasta the rejected values make up about two to the minus one hundred twenty-nine of each field. Each string of one hundred forty-three bits is the low part of exactly two to the one hundred eleven in-range values, so a uniform in-range value gives a uniform string.

An honest prover almost never meets a rejected value. The grinding that the statements and challenges chapter mentioned deals with the rare case for a challenge called pre-beta, the last challenge of the transcript and the one that becomes beta. There the prover re-randomizes the eval commitment and squeezes again until the value is in range.

Folding with an endoscalar.

Now we can rerun the fold of chapter thirteen with the real map. First we separate the challenges that act on foreign points from those that do not. On the first side, the challenges alpha and u only enter the folded value, which is native to the primary circuit. Only beta also scales commitments, so only beta has to be applied through a walk. The code matches this, using alpha and u as full field elements on the primary side.

The secondary circuit's accumulator needs challenges of its own, and it gets them by lifting the low bits of each primary challenge. The secondary alpha has no numeric relation to the primary alpha, and it does not need one, since the two batch different polynomials. For beta, both sides lift the same string.

We keep chapter thirteen's claims, two openings on each curve. That fold batches the two quotients with alpha into one polynomial with commitment F, then combines everything with beta in Horner form. The folded value is field arithmetic. The folded point starts from F and twice multiplies by beta and adds a commitment, so it needs two walks.

Some toy strings hit an exceptional addition, so we picked a pre-beta whose walks all finish, and Pasta needs no such choice. Let the transcript give alpha equal to eleven, u equal to thirteen, and pre-beta equal to thirty-one. The primary circuit uses alpha and u as they are, and it lifts pre-beta to beta equal to twelve. The secondary circuit uses only lifts of the same bit strings, which are six, twenty and five.

The primary circuit computes its folded value, three, with field arithmetic. It also walks the second curve's points by the bits, which act as the secondary beta, five. The secondary circuit computes its folded value, nine, and it walks the first curve's points by the same bits, which act as twelve.

The decider then works directly with the polynomials. It commits to the combined polynomial on each curve and evaluates each at its own side's u. All four numbers match, although neither circuit ever computed in the other's field.

Each folded point now takes forty-six gates, two walks of twenty and two additions of three. The four-bit double-and-add of chapter thirteen took sixty-eight gates for a shorter challenge. Each circuit also pays five gates to show that the bits are bits and three gates to lift them.

The field value has to be the lift, because the walk acts as the lift. Suppose the primary circuit used the integer thirty-one as beta in its field arithmetic. The walk takes the commitment F to twelve times F, and thirty-one times F is a different point. The value and the point would then describe different polynomials, and the decider would reject.

Transcript bridging.

The book's name for sharing one transcript between the two circuits is transcript bridging. Chapter thirteen explained why it is sound only with input consistency. We now have the tools to say how the lifted values reach the secondary circuit and how that circuit is held to them.

The secondary circuits see no transcript. They read every challenge from a stage of their own trace, committed without blinding on the curve whose coordinates are native to the primary circuit. So its commitment is a known combination of generators, with each lifted challenge multiplying its own generator.

The primary circuit cannot compute a lift, which lies in the other field. But walking a generator by the challenge's bits acts as exactly that lift, by the consistency property, and the generator has coordinates in the primary circuit's field. Chapter thirteen did this check with plain integers, and here is the real version.

The stage holds the lifted values six, twenty and five, with no blinding. The primary circuit breaks its three transcript values into bits and walks each generator by those bits. The three walks add up to the stage's commitment, in sixty-six gates. That circuit has no wires modulo thirty-one, and it still confirmed a commitment to exactly those values.

If the prover puts any of the thirty other values in the place of the secondary beta, the stage commits to a different point and the comparison fails. So the endoscaling walk has two uses in a fuse. It folds commitments, and it also certifies foreign field values.

A fuse has nine challenges, and the challenge stage holds the lifts of all nine, so walks of its generators bind every one of them. The code's stage also holds a sign that the base case uses, which we leave aside. The only difference for pre-beta is timing.

Pre-beta is squeezed only after the primary circuit has committed to the partial sum of the other eight walks. So the walk of pre-beta's generator, and the comparison with the stage commitment, happen one step later, in the next fuse's bind beta circuit.

One gap remains, and it concerns the bits. Each walk that folds commitments by beta reads its bits from a separate stage, and we have to tie those bits to pre-beta. On the primary side, a circuit called bind endoscalar extracts the bits from pre-beta again and compares them wire by wire.

The secondary side holds no pre-beta, only the lifted secondary beta. So its compute V circuit lifts its own bits and requires the result to equal the secondary beta. This check is only as strong as the lift is injective, as the toy curves show.

The string zero, zero, one, zero, zero also lifts to five in the field of size thirty-one, so a prover could load it and pass that comparison. In the field of size forty-three it lifts to five and not twelve, so the walk on the first curve produces a different point. The false accumulator has a value computed with twelve and a point computed with five.

Among the thirty-two toy strings, sixteen pairs agree in the smaller field and disagree in the larger one. On Pasta no such pair exists, by the norm bound. This is why the book cares about injectivity, beyond keeping the sample space large.

Why cheating fails.

We go through what a cheater can try, in the order of the earlier arguments. First, a second spelling of the challenge, which would let a prover pick its endoscalar after the hash. The range requirement leaves one spelling. The verifier rejects a proof whose challenge is out of range, and no in-circuit assignment exists for such a value.

Second, wrong lifts on the secondary side. The stage is unblinded, and the primary circuit recomputes its commitment from the transcript's bits. Any other value changes the point, under the discrete log relation assumption for that curve's generators.

Third, other bits in a walk. The primary side compares its bits directly with the transcript. The secondary side compares a lift, and on Pasta only one string has that lift.

Fourth, a lucky challenge. A short challenge has a smaller range, as chapter thirteen counted, and the lift adds a condition, which is that distinct strings must not pile up on the same scalar. Take a cheater who passes when the string lifts to one particular constant. With an injective lift, one string out of thirty-two would pass.

On the toy cycle the lift is not injective, and the cheater does best with the constant zero, which four strings reach. That is a chance of four in thirty-two, so a collision in the lift directly raises a cheater's chance.

On Pasta the lift is injective in both fields. Each challenge tests a polynomial identity of some degree, and a false identity has at most that many roots. With an injective lift, at most that many of the two to the one hundred forty-three strings land on a root. Adding these bounds over all the challenges bounds the chance that any false identity passes.

For the nine challenges of one fuse step, the book lists the root counts, and they add up to sixty-six thousand four hundred seventy-seven. That bounds the chance at about two to the minus one hundred twenty-six point nine eight, and we recomputed both the sum and the exponent. The book calls this a conditional accounting for one step and not a security theorem.

The book lists what a full argument would still have to cover, including an adversary's repeated Fiat-Shamir trials, and we do not go further than that here.

Fifth, using an endoscalar for a secret. Everything so far concerns public challenges. A secret of one hundred forty-three bits would be weak in any encoding. For an endoscalar, an attacker splits the expansion at a digit into a head and a tail that add up. An attacker tabulates the tail's multiples of the point and looks up the observed point minus each head's multiple.

On the toy curve, the attacker tabulates eight digit points and tries four heads. That is twelve operations against thirty-two for trying every string, and the search finds the string. At one hundred forty-three bits the same idea takes roughly two to the seventy-one point five work.

That is far below the roughly two to the one hundred twenty-seven of a generic discrete log search in a group of two to the two hundred fifty-four elements. So the book and the code restrict endoscalars to public values, and a blinding factor must not be an endoscalar. A public challenge faces a different event, in which a fresh value hits a root fixed beforehand, and this search does not apply.

The argument rests on these assumptions, and it is informal. Discrete log has to be hard on both curves, and the transcript hash has to behave as a random oracle. Every commitment has to enter the transcript before the challenges that test it, which is the input consistency of chapter thirteen. The base points have to lie on the curve, which the circuits enforce separately.

Two of the checks also finish later than the step they protect. The comparison with the challenge stage waits for the next step's bind beta circuit, and the accumulated claims wait for the decider at the root.

Feedback between the walks.

A circuit does at most four endoscalings, so walking many points by one string takes several step circuits. These step circuits have traces, those traces have commitments, and the other side then has to fold those commitments too. So we need to know whether this back-and-forth settles at a finite number. The book treats it as a convergence problem.

The book's model says that each circuit adds one endoscaling on the other curve. With four endoscalings per circuit, a round trip multiplies the added count by one sixteenth, and the terms form geometric series. For equal base counts, the feedback raises the count by a factor of one point three three.

The code counts differently. A fuse folds the commitments of both children, so one more step circuit on one side puts two more points into the walk on the other side. A round trip then multiplies the count by one quarter, and the feedback raises the count by a factor of two.

So the process converges in either model, and the factor is a modest constant. The series treats circuit counts as fractions and never rounds up, though, so we now iterate the code's own count. In the code, a walk folds the batched quotient's commitment, each child's trace commitments plus four more, and six from the current step.

The trace polynomials on the other side are a fixed set plus one per step circuit. At the commit this site pins, the fixed sets have twenty-two polynomials on the primary side and thirteen on the secondary side. The fold makes one endoscaling for each point after the first, and a step circuit does four, so we divide by four and round up.

We start from no step circuits, compute the point counts and the step circuits they need, feed those back, and repeat. The first round gives forty-one points on Pallas and fifty-nine on Vesta, which need ten primary and fifteen secondary step circuits. The need then rises to eighteen and twenty, then twenty and twenty-four, then twenty-two and twenty-five, then twenty-three and twenty-six.

In the sixth round the counts stop changing. The primary circuits fold ninety-three points of Pallas in twenty-three step circuits, and the secondary circuits fold one hundred five points of Vesta in twenty-six. These are the counts that the opening of the chapter quoted. The chapter on recursion in Ragu, chapter eighteen, lists the step circuits that carry these walks.

Endoscalars in Ragu.

What follows is reconstructed from the code at the commit this site pins, and the authors have not confirmed it. The nine challenges come from earlier chapters. The wiring and registry chapter drew w, x, y and z, the revdot chapter's quotient fold drew two more, and the batched openings chapter drew alpha and u. Pre-beta is the ninth.

The book's matrix fold also used two challenges called nu and nu prime, but the code's fold has one challenge per layer, so its transcript has no nu. The code calls the secondary copy of beta by the name beta n.

The endoscalar gadget holds one hundred forty-three Boolean wires, and the hoisted gadget adds two product wires per digit. The step circuits on both sides walk with the hoisted gadget. The binders walk constant generators by different strings, so they use the plain gadget.

Four bind challenges circuits walk the generators for two challenges each and export their partial sum. The next step's bind beta circuit adds pre-beta's term and compares the sum with the stage commitment. For the root proof, the verifier rederives the stage itself.

On the primary side, the compute V circuit extracts the string from pre-beta and lifts it for the folded value, and the prover does the same outside the circuit. The book reports Lean proofs of the gadget contracts for the walk and the lift, and says that the sharing of staged wires and the protocol's overall soundness lie outside them. We did not run those proofs.

The book and the code differ on four points, and this site follows the code on each. The first is which challenges are endoscalars. The book's transcript bridging section sets every verifier challenge to its extracted endoscalar and multiplies by it directly in the primary circuit. In the code, primary challenges other than pre-beta stay full field elements, and the primary circuit multiplies by the lift.

The book's endoscalar page agrees with the code on the nested lifts. Following the code settles the difference that chapter thirteen recorded.

The second is how a string reaches the other circuit. The book's endoscalar page makes the endoscalar a public output of the primary circuit and a public input of the secondary circuit. In the code, the secondary side holds the bits in a stage, and the checks of the bridging section tie them to pre-beta. The same page's later section on hoisting describes this design.

The third is out-of-range challenges. The book says a prover re-randomizes and tries again. In the code only pre-beta is ground this way, and for the other challenges the lift returns an error, an event the code puts at two to the minus one hundred twenty-nine. The difference has little practical effect.

The fourth is the feedback factor. The book has each circuit add one endoscaling on the other curve, and its closing arithmetic for a capacity of eight also writes the ratio inverted. In the code each step adds a point per child, which gives the larger factor. The reading that this explains the difference is ours, and the book may intend its model only as a simplification.

All of this describes the Ragu revision this site pins. Tachyon, which has not activated on mainnet and whose design is still changing, pins a different Ragu revision.

Where this leaves us.

Let's collect what we've built. On a curve whose equation sees x only through its cube, a cube root of one gives a map that multiplies every point by one scalar, lambda, at almost no cost. Each field of a cycle keeps one constant, which acts on its own curve's coordinates and as the eigenvalue on the partner curve, and these choices have to line up.

Elements of the ring built on lambda have one image in each scalar field. A radix-three walk reads a bit string as such an element, three bits per tripling, so the element determines the string. On Pasta the norm bound keeps strings distinct in both fields and rules out exceptional additions, while the toy curves show both failures.

A circuit lifts a string to get a value in its own field and walks the string to act on foreign points, so one string serves both circuits with no foreign arithmetic. The primary circuit holds the secondary circuit to the lifted values by walking generators, and the secondary circuit ties its bits to the secondary beta through injectivity. Step circuits feed work back to the other curve, and the count settles at a constant multiple of the first round.

Several of these mechanisms depended on stages, including the challenge stage, the stage that holds the bits and their hoisted products, and the bridge stages. The next chapter, on staging, explains how a circuit commits to its trace in parts and how the partial commitments are checked.
